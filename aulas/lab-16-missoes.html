Antes de começar

Seu sistema já roda na nuvem. Falta protegê-lo: só quem está autenticado acessa as rotas sensíveis, o tráfego vai cifrado (HTTPS) e nenhum dado pessoal vaza em log. Hoje você aplica isso ao gateway do C3.A2.

Pré-requisitos

  • Python 3.12 com fastapi, uvicorn, httpx e pyjwt (pip install pyjwt) ou o auth_demo.py como base (sem dependências).
  • O gateway do C3.A2 (ou o da Aula 14) para adicionar a proteção.
  • O exemplo da aula: aulas/exemplos/aula16/auth_demo.py.

Missão 1 — Entender o JWT entender ~15 min

Objetivo: ver que o JWT é assinado (integridade) mas não cifrado (o payload é legível).

cd exemplos/aula16
python auth_demo.py          # 4 casos: valido, adulterado, segredo errado, expirado

Copie o token impresso e cole em jwt.io: você lê o payload sem o segredo. Agora mude o exp no código e rode de novo.

  • rodei e vi os 4 casos (só o válido passa)
  • decodifiquei o payload em jwt.io (é legível!)
  • sei dizer a diferença entre integridade (assinatura) e sigilo (cifra)

🧭 Travou? Releia "Como um JWT funciona". IA (registre): "Por que o payload de um JWT pode ser lido por qualquer um, e o que exatamente a assinatura protege?"

✅ Entregável. Uma frase no relatorio_seguranca.md: por que não se guarda segredo no payload do JWT.

Missão 2 — Proteger o gateway com JWT construir ~25 min

Objetivo: exigir um token válido nas rotas sensíveis — requisição sem token recebe 401.

  1. Crie uma rota POST /login que valida um usuário fixo e devolve um JWT (use pyjwt ou as funções do auth_demo.py).
  2. Proteja /infer: leia o header Authorization: Bearer <token>, verifique a assinatura e a expiração; inválido → 401.
  3. Teste: sem token → 401; com token válido → passa; com token adulterado → 401.
# sem token -> 401
curl -i -X POST localhost:8000/infer -d "{\"texto\":\"oi\"}"
# com token
curl -X POST localhost:8000/infer -H "Authorization: Bearer <token>" -d "{\"texto\":\"oi\"}"
  • /login devolve um JWT
  • /infer sem token responde 401
  • /infer com token válido passa; adulterado é rejeitado

🧭 Travou? Use fastapi.security.HTTPBearer para ler o header. IA (registre): "Como ler e validar um token Bearer num endpoint FastAPI e retornar 401 quando invalido?"

✅ Entregável. Gateway com /login + /infer protegido (evidência dos 3 casos: sem token, válido, adulterado).

Missão 3 — HTTPS e logs limpos (LGPD) proteger ~20 min

Objetivo: cifrar o transporte e evitar vazar dados pessoais.

  1. HTTPS: confirme que a URL pública do deploy é https:// (o provedor entrega o certificado). Teste e registre.
  2. Segredo fora do código: leia o segredo do JWT de uma variável de ambiente, nunca fixo no fonte.
  3. Logs limpos (minimização): garanta que os logs não gravam o texto completo do usuário nem dados pessoais; logue só o necessário (ex.: o trace_id e o tamanho do texto).
  • URL pública em HTTPS confirmada
  • segredo do JWT vindo de variável de ambiente
  • logs sem dados pessoais (minimização)

🧭 Travou? IA (registre): "Quais principios da LGPD se aplicam a enviar o texto do usuario para uma API de LLM de terceiros, e como a minimizacao reduz o risco?"

✅ Entregável. No relatorio_seguranca.md: HTTPS confirmado, segredo em env e a política de logs (o que você passou a não logar).

Missão 4 — Fechar o C3.A2 + simulado ENADE entregar ~20 min

Objetivo: deixar o projeto integrador pronto para a entrega e revisar para a prova nacional.

  1. Garanta que o C3.A2 está completo: microsserviços conteinerizados, resiliência (circuit breaker), observabilidade (trace) e segurança (JWT/HTTPS/LGPD), com README de arquitetura.
  2. Escreva o breve relatório de trade-offs (CAP, custo, latência) pedido no enunciado.
  3. Resolva o simulado ENADE (disponibilizado no AVA). Revise pelos quadros Foco ENADE de cada aula.
  • C3.A2 completo (containers + resiliência + observabilidade + segurança)
  • README de arquitetura + relatório de trade-offs
  • simulado ENADE resolvido

✅ Entregável. C3.A2 pronto para a entrega da Aula 17 + simulado ENADE resolvido.

Desafios — para quem voar 🚀

  • Papéis (RBAC): faça uma rota que só aceita token com role=admin — autorização de verdade, além da autenticação.
  • Expiração curta + refresh: emita tokens com exp curto e implemente um fluxo simples de renovação.
  • Anonimização: antes de enviar o texto ao LLM, mascare padrões de CPF/e-mail com uma expressão regular. Mostre o antes/depois.
