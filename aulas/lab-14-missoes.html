Antes de começar

Você tem containers soltos; hoje eles viram um sistema. O docker-compose.yml descreve a stack e sobe tudo com um comando; os serviços se acham pelo nome na rede interna.

Pré-requisitos

  • Docker com o daemon rodando e o Docker Compose (já vem no Docker Desktop).
  • O exemplo da aula: aulas/exemplos/aula14/ (gateway/, inferencia/, docker-compose.yml, funcao/handler.py).
  • Para a Missão 3: uma conta grátis de nuvem com funções (ex.: AWS Lambda, Google Cloud Functions) ou o modo de função do Render.

Regra de ouro: peça ajuda — e registre

Pode usar docs, colegas e IA; registre no PROMPTS.md o que usou e o que fez com a resposta.

Missão 1 — A stack com um comando orquestrar ~15 min

Objetivo: subir gateway + inferência juntos e ver o gateway encontrar a inferência pelo nome.

cd exemplos/aula14
docker compose up --build        # sobe os dois servicos
# noutro terminal:
curl -X POST localhost:8000/infer -H "Content-Type: application/json" -d "{\"texto\":\"gostei, otimo servico\"}"
# {"via":"gateway","resultado":{"sentimento":"positivo","host":"<id>"}}

Repare: só o gateway tem porta publicada (8000). A inferência é interna — tente acessá-la direto e veja que não dá.

  • docker compose up subiu os dois serviços
  • /infer no gateway respondeu com o resultado da inferência
  • confirmei que a inferência não é acessível de fora

🧭 Travou? "no configuration file provided" = rode na pasta do docker-compose.yml. Gateway responde 502? a inferência ainda está subindo — aguarde. IA (registre): "Como os serviços de um docker-compose se encontram pelo nome? O que e a rede padrao do compose?"

✅ Entregável. A stack subindo com um comando (print do /infer funcionando).

Missão 2 — Escalar um serviço escalar ~15 min

Objetivo: ver a elasticidade na prática — mais réplicas, respostas vindas de hosts diferentes.

docker compose up --scale inferencia=3     # 3 replicas do servico interno
# dispare varios /infer e observe o campo "host" mudando entre as respostas
for /l %i in (1,1,6) do curl -s -X POST localhost:8000/infer -H "Content-Type: application/json" -d "{\"texto\":\"teste\"}"
  • subi 3 réplicas da inferência
  • vi o campo host variar entre as respostas (balanceamento)
  • anotei: o que acontece com --scale inferencia=1 de novo?

🧭 Travou? O host não muda? Dispare mais requisições (o balanceamento é por conexão). IA (registre): "Por que escalar horizontalmente (mais replicas) ajuda sob carga, e quando isso para de ajudar?"

✅ Entregável. Evidência (print/saída) das respostas vindas de hosts diferentes ao escalar.

Missão 3 — Publicar uma função serverless (3 medições) serverless ~25 min

Objetivo: entregar só uma função e medir o cold start na prática.

  1. Use o funcao/handler.py como base. Rode local: python funcao/handler.py.
  2. Publique a função numa plataforma FaaS (AWS Lambda / Cloud Functions / Render Functions) — adapte a assinatura do handler ao formato da plataforma.
  3. Meça o tempo de resposta três vezes: a 1ª após ficar ociosa (cold start), e mais duas seguidas (quente).

  • as 3 medições preenchidas
  • a 1ª (cold) é visivelmente maior que as quentes

🧭 Travou? Cada provedor tem um formato de handler. IA (registre): "Qual a assinatura de um handler no AWS Lambda (ou Cloud Functions) em Python e como ele recebe o event?"

✅ Entregável. A função no ar + a tabela das 3 medições no repositório.

Missão 4 — Compor a stack do C3.A2 entregar ~15 min

Objetivo: subir o projeto inteiro com um comando e integrar o componente serverless/edge.

  1. Escreva o docker-compose.yml do C3.A2 (gateway + inferência + worker + armazenamento vetorial). Só o gateway expõe porta.
  2. docker compose up: o projeto sobe inteiro com um comando.
  3. Integre o componente serverless/edge ao fluxo (ex.: um pré-processamento ou webhook).
  • projeto C3.A2 sobe com docker compose up
  • só o gateway é exposto; os demais são internos
  • componente serverless/edge integrado

✅ Entregável. O docker-compose.yml do C3.A2 subindo o projeto inteiro + o componente serverless integrado.

Desafios — para quem voar 🚀

  • Health check no compose: adicione healthcheck ao serviço de inferência e faça o gateway só subir quando ela estiver healthy (depends_on: condition: service_healthy).
  • Variáveis por ambiente: mova o INFER_URL e outras configs para um arquivo .env lido pelo compose.
  • Edge de verdade: sirva um arquivo estático por uma CDN (ex.: Cloudflare Pages) e meça a latência comparada ao seu serviço de origem.
